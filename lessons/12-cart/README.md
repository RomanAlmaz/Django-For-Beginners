# Lesson 12 - Cart (корзина и sessions)

Двенадцатый урок курса Django for Beginners. Вы продолжите проект из Lesson 11 и добавите **корзину** через Django sessions.

**Главная тема урока:** корзина через **Django sessions** (`request.session`).

## Что нужно знать до урока

View-функции, POST, словари Python, модели и `request`.

## Что не нужно запоминать

Внутренние помощники `_to_int()` и `_save_cart()`. Сначала разберитесь с обычным словарём session и публичными функциями корзины.

## Что изучается в этом уроке

- session и `request.session`;
- словарь `{product_id: quantity}` в session;
- добавление, изменение количества, удаление;
- итоговая сумма;
- `@require_POST` для изменяющих действий.

`shop/cart.py` - модуль с правилами корзины (не отдельный «service layer», просто вынесённая логика из views).

## Цель урока

**Главное:** понять, как положить словарь в `request.session`, прочитать его в следующем запросе и изменить через POST.

## Шаг 1. Что хранится в session

Session - данные конкретного посетителя между запросами. Корзина хранит только ID товара и количество:

```python
{
    '1': 2,
    '5': 1,
}
```

Основная механика состоит из трёх действий:

```python
cart = request.session.get('cart', {})
cart[str(product_id)] = quantity
request.session['cart'] = cart
```

Сначала прочитали словарь, затем изменили его и положили обратно в session. Остальной код `cart.py` добавляет проверки вокруг этой простой идеи.

Названия и цены не копируются в session. `get_cart_lines()` получает актуальные товары из базы по их ID.

## Шаг 2. Функции cart.py

| Функция | Что делает |
|---------|------------|
| `add_to_cart()` | добавляет количество к позиции |
| `update_cart_item()` | устанавливает новое количество |
| `remove_from_cart()` | удаляет одну позицию |
| `clear_cart()` | очищает всю корзину |
| `get_cart_lines()` | возвращает товары, суммы строк и общий итог |
| `get_cart_item_count()` | считает количество для шапки |
| `is_product_in_cart()` | проверяет наличие товара после обновления |

## Шаг 3. Серверная валидация количества

В `cart.py` количество проверяется на сервере. **Добавление** и **изменение** работают по-разному:

| Операция | Некорректное / `<= 0` | От `1` до `99` | Больше `99` |
|----------|------------------------|----------------|-------------|
| `add_to_cart` | добавить 1 товар | прибавить к текущему количеству | итог не больше 99 |
| `update_cart_item` | удалить позицию | установить новое количество | установить 99 |

Например, если в корзине уже 2 книги и пользователь добавит ещё 3, в корзине станет 5 книг.

HTML `max="99"` - только подсказка в браузере. Сервер проверяет сам.

**Учебный вывод:** HTML validation не заменяет server validation. Пользователь может отправить POST без браузерной формы.

Асимметрия намеренная и не является правилом Django:

- при добавлении неверное количество означает «попробовать добавить 1 товар»;
- при обновлении значение `<= 0` означает «удалить позицию».

## Дополнительно: удалённый товар

Если товар удалён из базы, но его ID остался в session, `cart.py` удалит такую устаревшую запись. Поэтому счётчик в шапке совпадает с содержимым `/cart/`.

То же самое, если ключ в session нельзя превратить в число: такая запись удаляется, страница корзины не падает.

Этот блок нужен для надёжности, но не является новой темой Django.

## Шаг 4. Views и URLs

Изменяющие действия принимают только POST:

```python
@require_POST
def cart_add(request, pk):
    ...
```

| URL | Действие |
|-----|----------|
| `/cart/` | показать корзину |
| `/cart/<id>/add/` | добавить товар |
| `/cart/<id>/update/` | изменить количество |
| `/cart/<id>/remove/` | удалить товар |

Формы содержат `{% csrf_token %}`. После POST view возвращает redirect, поэтому обновление страницы не повторяет действие.

## Шаг 5. Счётчик в навигации

Context processor добавляет `cart_item_count` в каждый шаблон:

```python
def cart(request):
    return {
        'cart_item_count': get_cart_item_count(request.session),
    }
```

Подключение в `django_shop/settings.py`:

```python
'shop.context_processors.cart',
```

Теперь `base.html` может показывать `Корзина (3)` на любой странице.
