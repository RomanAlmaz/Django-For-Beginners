# Lesson 12 - Cart (корзина и sessions)

**Главная тема урока:** корзина через **Django sessions** (`request.session`).

## Что изучается в этом уроке

- session и `request.session`;
- словарь `{product_id: quantity}` в session;
- добавление, изменение количества, удаление;
- итоговая сумма;
- `@require_POST` для изменяющих действий.

`shop/cart.py` - модуль с правилами корзины (не отдельный «service layer», просто вынесённая логика из views).

## Запуск

```bash
py -m venv venv
source venv/Scripts/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

## Серверная валидация количества

В `cart.py` количество нормализуется на сервере. **Добавление** и **изменение** - разная логика:

| Операция | Некорректное / отрицательное | 1..99 | > 99 |
|----------|------------------------------|-------|------|
| `add_to_cart` | → 1 | установить | → 99 |
| `update_cart_item` | → удалить позицию | установить | → 99 |

HTML `max="99"` - только подсказка в браузере. Сервер проверяет сам.

## Удалённые товары

Если товар удалён из базы, но остался в session, `cart.py` **очищает** stale id. Счётчик в шапке и содержимое `/cart/` всегда согласованы.

## Проверка

| Действие | Ожидание |
|----------|----------|
| **В корзину** на товаре | товар в корзине, счётчик в шапке |
| `/cart/` | таблица, итого |
| GET `/cart/5/add/` | 405 Method Not Allowed |

Корзина работает без входа в аккаунт.

## После этого урока

Вы должны уметь:

- хранить данные в `request.session`;
- вынести логику корзины в отдельный модуль;
- валидировать данные на сервере, не полагаться на HTML;
- использовать `@require_POST` для POST-only views.
