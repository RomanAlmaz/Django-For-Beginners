# Lesson 00 - Hello Django

Нулевой урок курса Django for Beginners. Вы создадите пустой Django-проект и запустите его - без своего кода, только то, что даёт Django из коробки.

## Что нужно знать до урока

Достаточно уметь открыть терминал, перейти в папку и выполнить команду.

## Что не нужно запоминать

Все настройки Django и все команды `manage.py`. Сейчас важно только создать окружение и запустить проект.

## Что изучается в этом уроке

- что такое Django;
- установка Python;
- virtual environment;
- установка Django;
- `django-admin startproject`;
- `manage.py`;
- запуск development server;
- структура Django project;
- `settings.py`;
- `urls.py`.

## Что такое Django

Django - это Python-фреймворк для создания веб-приложений. Он помогает быстро строить сайты, потому что уже содержит готовые решения для типичных задач: URL routing, работа с формами, админ-панель, безопасность и многое другое.

В этом курсе мы шаг за шагом построим учебный интернет-магазин **Django Shop**. Сейчас мы только создаём пустой проект.

## Требования

- Python **3.14.x** (рекомендуется; автор курса проверяет проект на **Python 3.14.3**);
- Django **5.2.12**;
- pip;
- Git (для удобной работы с репозиторием);
- браузер.

Рекомендуется Python 3.14.x. Python 3.10-3.14 теоретически поддерживаются Django, но автор курса тестировал курс на Python 3.14.3.

## Шаг 1. Клонируйте репозиторий

Если вы ещё не получили проект, склонируйте репозиторий курса через Git:

```bash
git clone https://github.com/RomanAlmaz/Django-For-Beginners.git
cd Django-For-Beginners/lessons/00-hello-django
```

Git нужен, чтобы легко получать обновления курса и переключаться между уроками. На Windows можно использовать обычный Command Prompt, PowerShell или Git Bash.

## Шаг 2. Создайте virtual environment

Virtual environment (виртуальное окружение) изолирует зависимости проекта от остальной системы.

**Windows (Command Prompt):**

```bat
py -m venv venv
venv\Scripts\activate.bat
```

**Linux / macOS:**

```bash
python3 -m venv venv
source venv/bin/activate
```

## Шаг 3. Установите Django

```bash
pip install -r requirements.txt
```

В `requirements.txt` указан Django 5.2.12 - той же версии, которую использует автор курса.

## Шаг 4. Изучите структуру проекта

Этот урок - результат команды:

```bash
django-admin startproject django_shop .
```

Структура проекта:

```
00-hello-django/
├── manage.py
├── requirements.txt
├── README.md
└── django_shop/
    ├── __init__.py
    ├── settings.py
    ├── urls.py
    ├── wsgi.py
    └── asgi.py
```

Обратите внимание: здесь **нет** `views.py` и **нет** приложения (`app`). Это чистый проект сразу после `startproject`.

### Важные файлы

| Файл | Назначение |
|------|------------|
| `manage.py` | Утилита для управления проектом: запуск сервера, миграции, создание приложений |
| `django_shop/settings.py` | Настройки проекта: приложения, база данных, язык, безопасность |
| `django_shop/urls.py` | Сопоставление URL-адресов с view-функциями (пока только `/admin/`) |

**Сегодня нужны:** `manage.py`, `settings.py`, `urls.py`.

**Пока игнорируем:** `asgi.py`, `wsgi.py`, `__init__.py`. Django создал их автоматически. К `asgi.py` и `wsgi.py` вернёмся в теме production/deployment.

### Project vs App

На этом уроке мы работаем только с **project** (проектом) - `django_shop`. Это контейнер для настроек и URL-адресов всего сайта.

**App** (приложение) - отдельная часть функциональности. Мы добавим его позже, в следующих уроках.

## Шаг 5. Посмотрите на urls.py

В `django_shop/urls.py` сейчас только один маршрут:

```python
from django.contrib import admin
from django.urls import path

urlpatterns = [
    path('admin/', admin.site.urls),
]
```

Главная страница (`/`) пока никуда не ведёт - Django ещё не знает, что на неё показывать.

## Шаг 6. Запустите проект

Примените миграции (Django создаст локальную базу SQLite):

```bash
python manage.py migrate
```

Проверьте проект:

```bash
python manage.py check
```

Запустите development server:

```bash
python manage.py runserver
```

Откройте в браузере: [http://127.0.0.1:8000/](http://127.0.0.1:8000/)

### Это нормально: стартовая страница Django

Если вы видите страницу Django с сообщением об успешной установке и рисунком ракеты - **всё работает правильно**. Сервер отвечает со статусом `200 OK`.

Это не ваша страница магазина. Django показывает её только потому, что проект запущен в режиме разработки, а для адреса `/` ещё не создана view.

| Что вы видите | Что это значит |
|---------------|----------------|
| Стартовая страница Django + ракета | Django работает, проект пустой |
| Ошибка в терминале | Нужно проверить установку |
| Белая страница без текста | Сервер не запущен или другой порт |

На следующем уроке мы добавим первую страницу, и ракета на `/` пропадёт.

Вы создали пустой Django-проект, разобрали его структуру и запустили development server. Проект работает - просто пока без своих страниц.

## Домашнее задание

1. Откройте `django_shop/settings.py` и найдите `DEBUG`, `INSTALLED_APPS`, `DATABASES`.
2. Откройте [http://127.0.0.1:8000/admin/](http://127.0.0.1:8000/admin/) - увидите страницу входа в админку (пока без суперпользователя).
3. Выполните `python manage.py` без аргументов и посмотрите список доступных команд.
